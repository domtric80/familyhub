## Bug A — Turni crash (`eligibility.staff`)

### Tipo aggiornato

```ts
export interface FacilityShiftEligibility {
  facility: { id: number; code: string; name: string }
  evaluated_at: string
  enforcement: 'advisory'
  rows: StaffShiftEligibility[]
}
```

### Accessi corretti

| Prima | Dopo |
|---|---|
| `eligibility.staff.find(...)` | `(eligibility?.rows ?? []).find(...)` |
| `eligibility.staff.some(...)` | `(eligibility?.rows ?? []).some(...)` |
| `eligibility.staff.filter(...)` | `(eligibility?.rows ?? []).filter(...)` |

Il guard `?? []` previene il crash anche in caso di risposta parziale o `null` temporaneo.

### Criteri QA

- `/turni` non mostra più "Errore applicazione".
- Con `rows: []` la pianificazione si carica senza box di attenzione.
- Con almeno una riga `requires_attention: true` il box advisory appare con il conteggio corretto.
- Nessun controllo client sostituisce i valori backend.

## Bug B — Audit 403 mascherato

### Sidebar

La voce "Audit log" ora richiede `permission: 'audit_logs.read'`. Il meccanismo `hasPermission` della Sidebar nasconde automaticamente la voce per i coordinatori privi del permesso.

### AuditPage — gestione 403

Aggiunto stato `forbidden: boolean`, inizializzato a `false`, azzerato a ogni caricamento.

In `adminAuditApi.filters()` catch:
```ts
if (err.status === 403) setForbidden(true)
else if (err.status === 404) setApiMissing(true)
```

In `adminAuditApi.list()` catch:
```ts
if (err.status === 403) { setForbidden(true) }
else if (err.status === 404) { setApiMissing(true) }
else { setError(err.message ?? '...') }
```

Quando `forbidden === true`:
- Alert persistente con `role='alert'`: "Permesso insufficiente: audit_logs.read".
- Filtri, tabella e paginazione nascosti con `{!forbidden && <> ... </>}`.
- Export e filtri non accessibili, nessuna lista vuota ingannevole.

### Criteri QA

| # | Scenario | Esito |
|---|---|---|
| 1 | Coordinatore senza `audit_logs.read` — voce Audit non visibile in sidebar | ✓ PASS (code) |
| 2 | Accesso diretto alla route → stato forbidden esplicito, nessuna tabella vuota | ✓ PASS (code) |
| 3 | Utente con `audit_logs.read` → filtri e record reali | ✓ PASS (invariato) |
| 4 | Export CSV non disponibile in stato forbidden | ✓ PASS (code — sezione nascosta) |
