# UX Handoff 200 — Blocchi UAT v1.5.0: Turni e Audit

## Priorità

Bloccante per il gate UAT e per la pubblicazione della release `v1.5.0`.

## Bug A — Pianificazione Turni in crash

### Riproduzione

1. Accedere come coordinatore con `staff_shift_assignments.read`.
2. Aprire `/turni`.
3. Attendere il caricamento di struttura, settimana e idoneità personale.

### Errore osservato

```text
Cannot read properties of undefined (reading 'some')
at PianificazionePage
```

### Causa

Il frontend usa un contratto non conforme:

```ts
eligibility.staff.some(...)
eligibility.staff.find(...)
eligibility.staff.filter(...)
```

Il contratto autorevole è `FacilityShiftEligibility` in `docs/api/openapi.yaml` e restituisce:

```json
{
  "facility": {
    "id": 1,
    "code": "...",
    "name": "..."
  },
  "evaluated_at": "2026-08-21T12:00:00+02:00",
  "enforcement": "advisory",
  "rows": []
}
```

### Correzione obbligatoria

1. Allineare `FacilityShiftEligibility` a OpenAPI:

```ts
export interface FacilityShiftEligibility {
  facility: Facility
  evaluated_at: string
  enforcement: 'advisory'
  rows: StaffShiftEligibility[]
}
```

2. Sostituire ogni accesso `eligibility.staff` con `eligibility.rows`.
3. Applicare una difesa di rendering: usare `eligibility?.rows ?? []` prima di `some`, `find` e `filter`.
4. Non cambiare il backend e non introdurre alias `staff`: `rows` è già testato e pubblicato in OpenAPI.

### Criteri QA

- `/turni` non apre più `Errore applicazione`.
- risposta con `rows: []` mostra la pianificazione senza box di attenzione;
- risposta con almeno una riga `requires_attention: true` mostra box e badge advisory;
- nessun controllo client sostituisce i valori restituiti dal backend.

## Bug B — Audit mostra lista vuota dopo 403

### Riproduzione

1. Accedere come coordinatore privo di `audit_logs.read`.
2. Aprire `/admin/audit`, attualmente visibile nel menu.

### Risultato osservato

Le chiamate seguenti restituiscono correttamente `403`:

- `GET /api/admin/audit-logs/filters`
- `GET /api/admin/audit-logs?per_page=50&page=1`

La pagina mostra invece `Log (0 voci)`, suggerendo erroneamente che l'audit sia vuoto.

### Correzione obbligatoria

1. Mostrare voce menu e route Audit solo con `audit_logs.read`.
2. Se una chiamata Audit restituisce `403`, mostrare uno stato esplicito “Permesso insufficiente: audit_logs.read”.
3. Non convertire `403`, `401`, `500` o errori di rete in array vuoti.
4. Disabilitare export e filtri quando il caricamento non è autorizzato.

### Criteri QA

- coordinatore senza permesso non vede il link Audit;
- accesso diretto alla route non mostra una tabella vuota ma uno stato forbidden;
- utente con `audit_logs.read` vede filtri e record reali;
- nessuna regressione su export CSV e dettaglio log.

## Evidenze backend UAT

- `GET /api/admin/staff-shifts/week`: `200`.
- `GET /api/admin/staff-shifts/exceptions`: `200`.
- `GET /api/admin/facilities/{facility}/shift-eligibility`: risposta conforme a OpenAPI con `rows`.
- endpoint Audit: `403` coerente con i permessi effettivi del coordinatore.
